# Foundation implementation contract

The initial runnable slice is an empty per-student workspace, metadata onboarding, arbitrary courses, manual materials, reported coursework progress, bounded learning handoffs, and imported calendar events. Real Google/eLC authorization and automatic collectors are later adapters. No imported personal datasets or credentials.

HTTP `/api/*` requires `authenticate(request, env)` from auth.js, returning a frozen `{tenantId, subject, issuer}` or throwing an error with a safe `code` and numeric `status`. The student DO is selected by `env.STUDENTS.getByName('student-v1:' + tenantId)`; ownership never comes from HTTP input. The DO exposes `dispatch({tenantId, op, data, operationId, expectedRevision})` and checks its bound owner. Only index.js calls it.

Store operations: `profile.get`, `profile.put`, `courses.list`, `courses.put`, `materials.list`, `materials.get`, `materials.put`, `progress.list`, `progress.put`, `learning.get`, `learning.put`, `connections.list`, `connections.put`, `calendar.list`, `calendar.put`, `receipt.get`, `account.export`, `account.delete`. Results are `{ok:true,...}` or `{ok:false,error,status}`. Read operations carry filter/identity in data. Write operations require bounded operationId and expectedRevision; exact retries return matching original receipts, conflicting reuse fails. One revision per resource; creates use0. Include returned record/revision and operation receipt. Learning accepts observed correctness and assistance separately; wrong/partial work never increases correct counts. Student progress supports reported/unknown only, not source-verified claims.

Each record has an id scoped to one student's DO. Courses: `{id,code,title,section,term_id}`. Profile: `{display_name,timezone,consent_version}`. Material: `{id,course_id,title,text,source_kind:'manual'}`. Progress: `{id,course_id,assignment_id,title,status,submitted,verification,note}`. Learning: `{course_id,session_id,observations:[{topic_id,outcome,assistance,evidence,next_step}],resume}`; outcome correct/partial/incorrect/unassessed; assistance independent/hints/explanation; evidence observed_response/learner_report/discussion_only. Connections: `{id,provider,site_url}` only metadata; server status needs_authorization or manual_import, never connected merely on save. Calendar: `{id,course_id,source_id,events,coverage}`; bounded parsed ICS events accepted by worker, server stamps observation and imported-only coverage. No remote URL fetch in this milestone.

HTTP routes map the resource collections above; PUT with JSON `{operation_id,expected_revision,...data}` and GET query filters. `/api/onboarding` GET returns profile/courses/connections/capabilities, PUT saves profile. `/api/calendar/import` POST accepts `{operation_id,expected_revision,id,course_id,source_id,ics}` then parses bounded text in worker before calendar.put. `/api/receipts/:operationId` GET. `/api/account/export` GET includes the verified `workspace_id` in its envelope, including for a retired account. The optional `X-Workspace-Id` equality guard is checked for all API reads and writes; it never selects an owner. `/api/account` DELETE requires `{operation_id,expected_revision,confirm:'DELETE_MY_WORKSPACE'}`; deletion semantics and retry behavior must be documented. UI receives same-origin authenticated requests; reject cross-origin mutations. No AI provider calls, background jobs, real Google/eLC connector or cloud deployment in this slice.
