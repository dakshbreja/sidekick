## Implemented

The seven tools list courses, list course material metadata, read versioned passages (2,000 characters per page), read saved course deadlines, resume a checkpoint, save a checkpoint, and recover its receipt. Tool arguments have no owner selector. Reads retain pagination and coverage limits. Material text is untrusted reference content; an assistant must not follow instructions embedded in it. No profile, calendar credential, arbitrary backend operation, coursework completion write, export or account deletion is exposed as a connector tool.

Checkpoints include course/session identity, topic, question, actual learner response, assistance, rubric criteria with response quotes, versioned source references, a next step, and an immutable test-only flag. The server attaches the exact saved source text and rejects stale versions, wrong-course materials and quotes absent from the response. It derives a conservative outcome from the reported criteria. These checks validate record structure and provenance, **not the truth of an AI judgment**. All assessments remain `assistant_report_unverified`, with mastery false; they never increment existing practice or coursework progress counts. Empty answers and absent evidence remain unassessed. Partial criteria remain partial. Semantically wrong but structurally valid judgments still require model evaluation.

The Tutor page reads the same checkpoint and displays its response, feedback and next step. The hosted-tutor prompt can include a newer non-test checkpoint when its source versions are among the selected passages. Older checkpoints, test checkpoints and mismatched source versions are excluded. This context wiring is covered with synthetic tests; real-model continuation from an external assistant has not been evaluated. The website still generates multiple-choice practice and does not implement an automatic written-response grader.

The existing transaction saves checkpoint, receipt and account revision together. Exact retries recover the original result even after a source changes. Changed packets with the same ID conflict; stale revisions fail. A process restart preserves the checkpoint. Account deletion removes current records and historical receipts. Checkpoint snapshots remain accessible in account exports until deletion, as do existing record histories.

## Course identity lookup

`study_resume` accepts either an opaque `course_id` or an exact course code/title in `course_query`, plus optional exact `term_id` and `section` filters. It searches only the caller's already-authorized course list, follows bounded pagination and refuses incomplete coverage. One exact match returns the checkpoint and `resolved_course.id` for subsequent source reads and saves. Repeated codes across terms/sections return `course_ambiguous` with only authorized course metadata; no checkpoint is selected. Unknown and unauthorized names share the same error. No fuzzy matching or implicit current-term preference is used. Older clients that put a code in `course_id` get the same unique-match resolution; actual opaque IDs take precedence. Other tools and all saves still require exact IDs.

## Normal study versus simulation resume

Course-wide resume now defaults to `scope: learning`, selecting only non-test checkpoints. A newer simulation cannot replace the normal continuation, and a test-only course returns no normal checkpoint. Explicit `scope: test` selects the latest simulation. An exact `session_id` can still recover either kind for receipts/review; combining it with a scope further restricts the result. Invalid scopes fail closed. These are read filters, not record migration or new access permissions.

The Tutor page starts in normal study view. An explicit simulation checkbox reveals the separate test checkpoint and resets on reload or course/account changes. Prepare Claude continuation produces a reviewable prompt with only course/session identifiers, the selected scope and study instructions; it includes no material passages or learner answers, sends nothing, and grants no access. The prompt requires the existing approved connector, stops on missing/revoked access, preserves test-only saves and asks for save confirmation. Other providers retain the manual material-handoff path.

## Automatic source-version check

Every resume includes `source_check` with `status`, `can_use_saved_sources`, `checked_at`, `checked_account_revision`, per-source saved/current revisions, `scope: current_bridge_material_versions`, `upstream_freshness: unknown` and `next_action`. It is computed synchronously from the same student store on every read; it is not a cached checkpoint field. Every saved reference must retain its revision, same-course ownership, valid bounds and exact excerpt text for status `current`. Missing or wrong-course sources return `unavailable` without exposing another course's metadata; any unavailable source takes precedence over changed sources. No checkpoint returns `no_checkpoint`. Only `current` permits using the saved excerpts.

Changed sources require a fresh material read at the returned current revision, starting at zero because offsets can move. Unavailable sources require an available replacement selected by the learner. The assistant must not silently regrade historical responses or claim that eLC was checked. Resume does not write, migrate or replace history. A subsequent save still validates source revisions; an exact historical retry still recovers its original receipt. The website shows the check and embeds its handling rules in the prepared continuation. This check does not guarantee model compliance or source-collector freshness.

For a disposable changed-source browser fixture, run `DEMO_STUDY=1 DEMO_STUDY_CHANGED=1 DEMO_PORT=8774 node scripts/demo.mjs`. Open Student A's Tutor page and enable simulation checkpoints. Its saved five-unit buffer excerpt stays historical while the current material has an eight-unit buffer. Student B has no checkpoint. No real materials or model calls are used.

## Reversible material editing and archiving

The Notes page can edit a material using its current revision and the existing durable save/receipt queue. Course identity stays immutable. The optional boolean `archived` marks a material unavailable for new teaching; owner library reads and historical checkpoints remain available for review. Connector metadata exposes the archive state, while passage reads and new checkpoint source validation reject archived materials. Website material selection excludes them, manual handoffs recheck their current state, and new tutor inference rejects them before calling a provider. Existing revision fencing also prevents a model reply from saving after its source is archived during inference.

Restore by clearing the archive checkbox. Both archive and restore create a new revision, so a historical checkpoint requires a current read before continuation. Exact retries still recover original receipts. This is reversible withdrawal from teaching, not erasure or recall of content already sent to a provider. No deletion endpoint or administrative test bypass was added.

## Local interfaces

- `GET /api/study?course_id=...&session_id=...` (session and scope optional): resume through the normal authenticated website boundary.
- `PUT /api/study`: the same save contract as the connector, with `operation_id` and `expected_revision`.
- `POST /api/study-connector-preview`: JSON-RPC adapter for `initialize`, `ping`, `tools/list` and `tools/call`. Requires `STUDY_CONNECTOR_PREVIEW=true`, a verified Access assertion, exact `X-Workspace-Id`, existing origin protections, and a body no larger than 40 KB. Disabled by default and not enabled on the hosted site.
- The website has no public `/mcp` route. The separate connector service implements stateless Streamable HTTP POST responses, MCP `2025-06-18`, OAuth discovery, authorization-code/refresh/revocation endpoints and Claude DCR. The installed instruction-only plugin stays unchanged.

Run `DEMO_STUDY=1 DEMO_PORT=8773 node scripts/demo.mjs`, then open the local `/tutor` page. The disposable demo seeds two synthetic accounts and saves a partial-reasoning checkpoint for A through the protocol. B stays separate. It uses no real AI or external school sources. Run `node --test test/study-connector.test.mjs` for the connector contracts, actual workerd/SQLite restart and two-identity isolation checks.

## Remote authorization and revocation

`src/connector-worker.js` uses pinned `@cloudflare/workers-oauth-provider` 1.2.3 for OAuth 2.1, S256 PKCE, client registration, token lifecycle and exact resource audience checks. Registration is restricted to Claude’s documented HTTPS callback. CIMD and arbitrary redirects are disabled in this private pilot. Tokens expire after 15 minutes; refresh grants and the independent Bridge grant expire after seven days. New authorization requires explicit consent, with read-only versus checkpoint-save choices and one to twenty selected courses. After approval, an explicit Return to Claude link completes the callback in the browser where the connection started. This avoids forcing an immediate redirect into an unrelated browser session; the callback remains pinned to Claude and protected by the existing single-use code and PKCE checks.

The existing website retains its all-traffic Cloudflare Access policy. Its verified issuer/subject identity, never a browser-supplied email or owner ID, approves the grant through a private service binding. Public OAuth state is a bounded ten-minute, single-use durable request. The consent page uses strict same-origin writes and an exact workspace header. OAuth endpoints have a global private-pilot ceiling of 60 requests/minute and 100/day to bound free-tier token-store writes. This small pilot budget is not a public-service capacity claim.

The connector can call only a narrow internal service entrypoint. Every tool call checks the student-local grant, expiry, scopes, selected courses and account tombstone. Every save rechecks these in the same SQLite transaction as its write and receipt, after asynchronous hashing. Lists, source reads, checkpoints and receipts remain scoped to selected courses. Revoking at `/ai-access` blocks existing reads, saves, save retries and token refresh immediately at the Bridge boundary; it does not erase content already read by Claude. Account deletion clears the local grants and retires their identity. The OAuth provider also implements standard token revocation; its token records use Cloudflare KV, while immediate Bridge revocation uses the strongly consistent student object.

Deploy the generic `wrangler.connector.jsonc` only with a separate community KV binding, canonical connector/website origins and a service binding to the website’s `ConnectorBackend`. Add the reverse `CONNECTOR_AUTH` binding to the website and explicitly enable `CONNECTOR_ENABLED`. Generic configs remain disabled; actual owner configuration and resource IDs stay outside Git. No shared provider API key, browser Access token forwarding or personal Bridge dependency is introduced. The site’s AI-connection link appears only when configured.
