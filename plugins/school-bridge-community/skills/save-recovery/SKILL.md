# Recover an uncertain School Bridge save

Copyright 2026 Daksh Breja. All rights reserved.

This instruction-only package cannot inspect live records, receipts or local browser storage. Do not say a write saved, failed definitively or was deleted based on a chat description alone. Do not request secrets, exported workspace contents or another student's IDs. Use only the user's description of the visible application state.

1. Explain that a missing response may mean the server already saved the change. Do not suggest creating a fresh operation, changing values and resubmitting, or clearing site data before reconciliation.
2. Ask the user to confirm they are in the intended account through the application's sign-in and overview. A student ID or email supplied in chat cannot choose an owner. When sign-in changes, pending work belongs to the original account; it must never be replayed in another workspace.
3. Guide them to **Check receipts and recover saves** in the application's recovery panel. Explain that this is an explicit action: the app checks its authenticated receipt first, and only receipt-not-found allows the unchanged original packet to be retried. A matching receipt completes recovery without applying a duplicate write.
4. If the app reports authentication loss, a changed account, mismatched receipt, storage error or conflict, keep the original intent pending. Explain the actual error and the next relevant step; never treat an unavailable receipt service as proof that the save did not happen.
5. For deletion, use the application's deletion receipt or verified retired-account state to confirm cleanup. Deletion retires that identity in this foundation. Other accounts' pending packets remain separate, and an offline browser cannot be wiped remotely.
6. If the original browser profile was lost or site storage was cleared, say client recovery intent may be gone. The user needs a supported authenticated record/receipt inspection before recreating an uncertain write. This package cannot perform that inspection; do not invent a recovery result or obtain someone else's account access.

Pending text and calendar input may remain in plaintext in the original browser until reconciliation or confirmed deletion. Explain this when relevant, especially on shared devices. Browser restart recovery is not provider backup restoration, and it does not establish end-to-end encryption.
